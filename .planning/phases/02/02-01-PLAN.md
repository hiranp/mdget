# Plan 02-01: Request Surface and Typed Output Selection

## Objective

Implement request customization and output-mode selection plumbing with strict CLI validation and transport precedence guarantees.

## Task List

1. Add fetch CLI flags and typed propagation

- Update fetch command flags in `src/cli.rs` for repeatable `-H/--header`, repeatable `--cookie`, `--bearer`, `--json`, and `--no-frontmatter`.
- Enforce `--json` and `--no-frontmatter` mutual exclusivity at parse time.
- Define `RequestOptions` and `OutputMode` data types in `src/fetch/mod.rs` (or `src/fetch/request.rs`).
- Update `FetchOptions` in `src/fetch/mod.rs` to include `request: RequestOptions` and `output_mode: OutputMode`.
- Wire new arguments through `src/main.rs` and `src/commands/fetch.rs` into the updated typed fetch options.

1. Implement request parsing and transport injection

- Add strict `Name: Value` header parsing and deterministic cookie merge in `src/fetch/request.rs`.
- Update `src/fetch/http.rs` to apply headers/cookies and inject bearer authorization.
- Enforce precedence: `--bearer` overrides any `Authorization` value provided by `-H`.

1. Add request-surface integration tests

- Add/expand tests in `tests/fetch_request_options_integration.rs` for:
  - header parse success/failure,
  - cookie merge ordering,
  - bearer precedence,
  - CLI conflict behavior for `--json` vs `--no-frontmatter`.

## Verification Commands

- `cargo test --test fetch_request_options_integration`
- `cargo test cli:: -- --nocapture`
- `cargo clippy -- -D warnings`

## Acceptance Criteria

- HTTP-04/05/06 are satisfied with deterministic and validated request behavior.
- OUT-02/OUT-03 mode selection flags are parsed and propagated as typed options.
- Conflicting output flags fail with a clear CLI error.
- Existing fetch invocation without new flags remains functional.
