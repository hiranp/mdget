# Plan 02-02: Content-Type Router and Handler Matrix

## Objective

Add a normalized content-type router and per-type handlers while preserving HTML behavior as the compatibility baseline.

## Task List

1. Introduce router and keep HTML baseline behavior

- Add `mime`, `feed-rs`, `serde_json`, and `pdf-extract` (optional feature) to `Cargo.toml` dependencies.
- Add content-type normalization/routing in `src/fetch/router.rs` (strip parameters, normalize case).
- Update `src/fetch/mod.rs` to dispatch through router.
- Keep HTML/XHTML path semantically equivalent to current behavior (compatibility lock).

1. Implement JSON and plain-text handlers

- Add JSON handler in `src/fetch/handlers/json.rs` for `application/json` and `*+json`.
- Add plain-text handler in `src/fetch/handlers/text.rs` for `text/plain`.
- Register handlers in `src/fetch/handlers/mod.rs` and dispatch from orchestrator.

1. Implement feed/XML and PDF handlers with deterministic fallback/failure classification

- Add feed handler in `src/fetch/handlers/feed.rs` for RSS/Atom and feed-like XML.
- Add XML non-feed fallback rendering in the same flow (fenced XML block path).
- Add PDF handler in `src/fetch/handlers/pdf.rs` and ensure extraction failures map to predictable `pdf_extraction_failed` classification.

## Verification Commands

- `cargo test fetch::handlers:: -- --nocapture`
- `cargo test fetch::router -- --nocapture`
- `cargo test --test fetch_envelope_integration -- --nocapture`

## Acceptance Criteria

- CONT-01..05 are covered by deterministic router dispatch and handlers.
- HTML output remains compatibility-equivalent to baseline behavior.
- Non-feed XML fallback and PDF extraction failure modes are predictable and non-panicking.
